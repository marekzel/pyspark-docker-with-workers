# PySpark + Docker: 3-Container Project

A small project for learning Apache Spark Standalone, PySpark, and Docker Compose.

## Architecture

The project contains three containers:

- `spark-master` — Spark Master and Spark UI
- `spark-worker-1` — Spark Worker
- `spark-worker-2` — Spark Worker

The Spark Master coordinates the Spark application and distributes work to the two workers.

### Spark UI

Open:

http://localhost:8080

Worker UIs:

- http://localhost:8081
- http://localhost:8082

## Requirements

You need:

- Docker
- Docker Compose

On modern Docker installations, Compose is available as:

```bash
docker compose
```

## Start the Cluster

From the project directory:

```bash
docker compose build
docker compose up -d
```

Check the running containers:

```bash
docker compose ps
```

You should see:

- `spark-master`
- `spark-worker-1`
- `spark-worker-2`

Open the Spark UI:

http://localhost:8080

You should see both workers registered with the Spark Master.

## Run the PySpark Job

Run the application from the Spark Master container:

```bash
docker compose exec spark-master   /opt/spark/bin/spark-submit   --master spark://spark-master:7077   /opt/project/src/main.py
```

The application:

1. Reads transaction data from CSV.
2. Reads card information from CSV.
3. Joins the two datasets.
4. Groups transactions by card.
5. Calculates total amount, transaction count, and average transaction amount.
6. Writes the result as Parquet.

## Output

The result is written to:

```text
output/card_summary/
```

The directory contains Parquet files generated by Spark.

```bash

```

## What to Experiment With

This project is intentionally small so that you can experiment with Spark.

### Partitions

Try changing:

```python
.config("spark.sql.shuffle.partitions", "4")
```

to different values and observe the effect in Spark UI.

You can also experiment with:

```python
repartition()
```

and:

```python
coalesce()
```

### Caching

Try caching a DataFrame:

```python
transactions.cache()
```

Then run multiple operations against it and compare the execution in Spark UI.

### Joins

Experiment with:

```python
join()
```

and later try:

```python
broadcast()
```

for small lookup tables.

### File Formats

Compare CSV and Parquet.

For example:

```python
df.write.parquet("/output/example")
```

Parquet is generally much more suitable for analytical workloads than CSV.

### Number of Workers

Stop one worker:

```bash
docker stop spark-worker-2
```

Run the job again and observe what changes.

Start it again:

```bash
docker start spark-worker-2
```

This is a simple way to see how Spark distributes work across multiple workers.
